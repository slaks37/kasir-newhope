## Metode
- **Statis**: typecheck seluruh tree, hygiene, semua suite test, pembandingan bundle Vercel dengan source.
- **Dinamis**: stack lokal (`npm run dev`, PGlite) + build produksi frontend, auth tiruan Supabase, browser di-drive lewat DOM, proxy yang bisa memutus jaringan dan **membuang ACK** setelah server commit.
- **Volume**: 10 / 1.000 produk; 100 / 10.000 / ±100.000 transaksi (±250.000 item) lewat API asli. `EXPLAIN ANALYZE` pada query laporan.
- **Load**: 1 / 5 / 10 / 50 kasir virtual bersamaan (jual → poll state → laporan hari ini).

**Batasan**: PGlite berjalan satu thread dan tidak menjalankan autovacuum/ANALYZE, sehingga angka absolut dan angka load adalah **batas bawah**. Bentuk query plan dan rasio sebelum/sesudah berlaku juga di Postgres. Ulangi load test di staging Postgres.
