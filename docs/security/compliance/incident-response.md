# Incident response playbook — draft; contacts/legal approval required

Assign incident commander, security operator, privacy/legal lead, merchant communications and payment-provider liaison [OWNER VERIFY actual names/backups/contacts]. Use a private incident record; never publish payloads, credentials or customer exports in GitHub issues.

1. Triage: start incident clock, record detection/occurrence times and uncertainty, affected tenants/outlets/systems/providers, access path and evidence hash. Confirm scope with metadata/minimum samples. Distinguish exposed SQL grants from actual externally readable API/data access; do not claim exfiltration without evidence.
2. Contain: protect ordinary sales where possible; isolate affected endpoint/credential/role or optional external processing. Require reviewed dependency map before global grants/RLS/auth changes. Revoke stolen sessions/secrets and disable unsafe privileged actions; do not destroy audit/ledger or overwrite incident evidence.
3. Preserve: restricted logs, DB ACL/schema snapshots, immutable audit, request IDs and provider events; record custody and authorized investigator access. Keep evidence encrypted with approved retention; avoid raw PII in application logs or this repo.
4. Investigate: verified principals, tenant/outlet cross-scope attempts, browser grants/RLS/exposed schemas, provider webhook signatures/replays, PIN attempts/grants, offline device state and AI wire payloads. Correlate without assuming static QRIS nominal match identifies an order. Determine processor/controller obligations and cross-border impact.
5. Notify: privacy/legal determines whether incident constitutes failure of personal data protection. UU PDP Article 46 provides written notification no later than 3 x 24 hours to subjects and institution, with specified incident information; establish trigger, recipients, institutional channel and applicable current implementation with counsel immediately. Processor notifies merchant controller promptly under DPA, rather than waiting for full certainty. Required public notification and other payment/consumer obligations: counsel/provider assess. Do not send external notices without human authorization.
6. Recover: tested reversible/additive fix, staging negative tests, owner-approved deployment, verify data integrity/cross-tenant denial and compare financial totals. Reapply deletion tombstones after restore. Restore only known secure builds; don't re-enable vulnerable PIN/grants as convenience rollback.
7. Close: document evidence, root cause, containment, notifications, recovery checks and remaining risk. Correct notice/subprocessor/retention records; independent follow-up verification and owners/dates. No claim of compliance/certification from running tests alone.

Primary legal text: [official UU 27/2022 Article 46](https://jdih.komdigi.go.id/produk_hukum/view/id/832/t/undangundang+nomor+27+tahun+2022). Approved notification contacts and all statutory applicability determinations remain release prerequisites.
