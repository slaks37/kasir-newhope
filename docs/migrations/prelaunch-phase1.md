## Rencana cutover konkret — hanya setelah approval final

1. Owner terima custody key backup terpisah dan verifikasi recovered-key sesuai runbook escrow. Konfirmasi perangkat development yang dipakai dan tutup writer/outbox/in-flight; hentikan job penulis seperti blog automation selama jendela migrasi yang disetujui. Tidak melakukan ini sekarang.
2. Target adalah clean candidate di atas, **bukan** branch fixture. Manifest `neon/targets/hybrid-candidate.json` masih `productionEligible:false`. Runtime `HYBRID_RELEASE_TARGET=hybrid-candidate` ditolak sampai eligibility diubah melalui commit approval yang direview; env saja tidak dapat mengangkat staging. Setelah eligibility disetujui, alat restore menolak target itu agar tidak menimpa database rilis.
3. Di bawah freeze yang disetujui, jalankan kembali fingerprint read-only sumber dan kandidat. Harus cocok seluruh 125 tabel, UUID/scopes, finance, credential dan sequence. Bila drift ada, abort; review delta lengkap atau restore baru pada target terisolasi yang tersedia. Jangan memaksa upsert atau menghapus data. Jangan memakai checkpoint unfrozen lama sebagai final watermark.
4. Review/eksekusi handoff trigger bisnis signup Supabase dari script yang disiapkan; login/token/MFA/Storage tetap Supabase. Record source watermark, verifikasi canonical source account inventory. Jangan membuka signup bisnis baru sebelum provisioning Neon dan timestamp gate diuji/diterima.
5. Diff env produksi yang diajukan: restricted pooled `DATABASE_URL` candidate (nilai privat), project/branch candidate, `NEON_DB_PHASE1=1`, `HYBRID_RELEASE_TARGET=hybrid-candidate`, `VITE_NEON_DB_PHASE1=1`, Supabase Auth/Storage frontend+backend, native/Better Auth pilot off, `HYBRID_STAGING=0`, `VITE_HYBRID_STAGING=0`, `DOKU_PAYMENTS_ENABLED=0`, **tanpa** `HYBRID_REHEARSAL_TARGET`. Metadata env proyek tidak memiliki ANALYTICS_DATABASE_URL; kode analytics memakai fallback DATABASE_URL. Bila override ditambahkan nanti, guard harus memverifikasi host/role/branch sama. Source Auth/Storage/service-role integration tetap; upload/support write tidak diuji ulang dan tidak diklaim PASS baru. Channel pembayaran tidak diaktifkan pada migrasi ini. Diagnostic kandidat pooled restricted login lulus certificate TLS, READ ONLY dan least privilege; diagnostic lokal bukan bukti deployment produksi aktif. pg_stat_ssl backend false tidak membuktikan transport internal provider terenkripsi; certificate verification tetap wajib.
6. Setelah exact commit approval PASS CI/Preview, promote target yang disetujui. Awali writer tetap ditahan; cek existing Supabase login, directory/tenant/outlet, dashboard, entitlement, Storage read dan checkout tetap dijeda. Baru buka satu writer development terkontrol dan cek ACK/ledger/stock, kemudian writer uji lain. Catat marker first-Neon-write. Tidak ada transaksi pelanggan/pembayaran nyata di smoke test.

Downtime produksi **belum diukur**: angka komponen/rehearsal tidak memasukkan penghentian developer/jobs, final watermark/delta, env deployment propagation dan owner acceptance. Ukur freeze→ACK pada pelaksanaan yang disetujui; jangan menjanjikan downtime dari penjumlahan angka terpisah.

## Rollback final

Sebelum first-Neon-write: writer tetap ditahan, pastikan tidak ada provisioning bisnis baru yang terlewat, pulihkan deployment/env dan source signup provisioning sebelumnya, verifikasi sumber lalu buka satu writer. Candidate/backup dipertahankan.

Setelah Neon menerima write: hentikan kedua writer, simpan snapshot Neon/sumber, outbox, ACK dan audit; jangan hanya mengganti DATABASE_URL. Untuk closure finansial yang diuji, reverse journal mempertahankan UUID/client keys dan menolak konflik. Perubahan di luar closure itu (signup/membership baru, catalog, refunds, subscriptions, integrations) memerlukan delta/reverse delta lengkap yang direview atau perbaikan maju; jangan mengklaim otomatis aman. Tidak menghapus riwayat atau overwrite financial ledger; gunakan compensating entry bila diperlukan. Rekonsiliasi penuh dan acceptance diperlukan sebelum source dibuka kembali. Selama validasi awal pre-launch, tahan signup dan pembayaran sehingga boundary rollback tetap terkontrol.

## Keputusan dan tindakan yang tersisa

Engineering database pre-launch dan sintetik PASS. **Eksekusi NO-GO sementara** untuk custody backup, penerimaan scope perangkat development/ACK, final freeze/no-drift serta persetujuan commit/target/env di atas. Ini gate rilis yang konkret, bukan permintaan fleet pelanggan atau full GoTrue/Docker. DOKU provider E2E tetap gate pembukaan pembayaran tersendiri. Tidak membeli resource; kedua branch baru masih dalam paket free (10/10 slot setelah pembuatan), tidak boleh menambah resource berbayar tanpa approval.
